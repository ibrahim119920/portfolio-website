01 · Camera & lanes

Highway Lane Occupancy & Hogging Detection

A prototype that reads recorded highway video · one camera · six lanes

github.com/ibrahim119920/highway-lane-analytics

This project watches recorded highway video and works out which lane each vehicle is in, how long it stays there, and whether it stays in the passing lane longer than the rules allow. Each finding comes with a snapshot and a short video clip.

  • The road is divided into six lanes on screen, so one setup can work with different camera resolutions.
  • For large vehicles close to the camera, the system uses the bottom corner of the vehicle instead of the middle, so it does not jump between lanes.
  • A lane change is only recorded after it is seen for several frames. A hogging signal is a rule match, not a legal violation.

02 · Data platform

Highway Lane Analytics — Data Pipeline & Dashboard

A service that receives the events, checks them, stores them in layers, and shows the results

highway-lane-analytics-data-pipeline · private repository

This project receives the event files, checks them, removes duplicates, and stores them in layers so they can be used for analysis. A dashboard then shows lane usage, vehicle types, hogging signals, and data quality.

  • A secure receiving service accepts events in batches and rejects bad records instead of stopping the whole process.
  • The same data can be sent again without double-counting. In testing, 111 events and 158 vehicle tracks were processed with no rejected records.
  • The dashboard has four pages: overview, lane analysis, hogging explorer, and run quality.

What to keep in mind. This is a prototype using one camera and two short videos. Replaying old data is not live detection. A hogging signal is a rule match, not a violation. Vehicle counts are a lower bound because the tracker can lose an ID after a vehicle is blocked from view.

03 · Large data

NYC Mobility Lakehouse

Nine months of New York City taxi trips · about 30 million records

github.com/ibrahim119920/nyc-mobility-lakehouse

This project processes nine months of New York City taxi trip data — more than 30 million trips — and turns it into clean summary tables for analysis.

  • The same monthly job can be run again without adding duplicate data.
  • Data fingerprints and version history show that a rerun produces the same result.
  • The summary tables match the detailed data with zero difference, then support 12 analysis questions about time, place, payment type, and trip length.

04 · Platform design

NusaCommerce Data Platform

A design for moving online-store data from the order database to reports and dashboards

github.com/ibrahim119920/nusacommerce-data-platform

This project designs a data platform for an online store: data comes from the order database, passes through clear layers, and ends in reports and dashboards.

  • The first working path loads new orders only, in small pages, and remembers where it stopped.
  • Each load is saved only after it is complete, so a failed run can be retried safely.
  • Data quality and freshness targets are part of the design, not an afterthought.

01 · Local software

Photobooth — Local-First Kiosk Prototype

A self-service photo booth that keeps its data on one device and connects to a camera

Private repository

This is a photo booth prototype for one device. The screen, the local database, and the saved photos all live on the same machine, while a small service connects to the camera.

  • Only one photo session can be active at a time, so two customers cannot accidentally share a session.
  • Commands are safe to repeat, every important action is logged, and the local data can be checked or backed up.
  • The camera connection can be tested without a physical camera, which makes the rest of the flow easier to develop.

A team marketplace for game accounts · my work focused on transactions and payment

github.com/aufaanggara/rekberin
