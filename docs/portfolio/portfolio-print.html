01 · Computer vision

Highway Lane Occupancy & Hogging Detection

Single-camera prototype · prerecorded video · CPU-first · 56-vehicle ground truth

github.com/ibrahim119920/highway-lane-analytics
Portfolio page · michiportfolio.vercel.app

Maps highway CCTV vehicles to six normalized lane polygons with YOLO11n and ByteTrack, then emits typed lane events and rule-based lane-hogging indications. The rule set was rebuilt against 56 manually labelled vehicles, lifting F1 from 0.54 to 0.93.

  • Lane membership is voted across five points on the bottom edge of each box, restricted to the travel direction, fixing wide near-field truck misassignment.
  • Legitimate overtaking is exempted using relative position and speed; the decision is made when the lane stint ends, so the whole pass is visible.
  • Rules monitor lanes 2 and 3. On 56 reviewed vehicles, false positives fell 9 to 5 and missed hoggers 24 to 1; per-frame replay reached 0.909 F1.
  • Eight-second evidence clips and thumbnails are rendered on the Kaggle computation unit and published to Nextcloud; the event record keeps the clip path, not the video itself.

02 · Streaming data

Highway Lane Analytics — Data Pipeline & Dashboard

FastAPI receiver · Kafka · DuckDB / Parquet medallion · Streamlit · local prototype

highway-lane-analytics-data-pipeline · private repository
Portfolio page · data pipeline & dashboard

A replay-fed data platform that receives the vision project's event batches, validates and de-duplicates them, publishes to Kafka, and builds bronze, silver, and gold layers for a four-page Streamlit dashboard.

  • FastAPI receiver with bearer-token auth, batch limits, deterministic event keys, and de-duplication before publishing.
  • Three Kafka topics keyed by camera_id; consumer quarantines invalid records and commits offsets only after a successful write.
  • Silver facts for runs, events, tracks, and lane stints; gold aggregates lane usage, class mix, hogging, transitions, and run quality. Replay is idempotent.
  • Clips and thumbnails live in Nextcloud; the dashboard maps event metadata to those files and streams them inline through a server-side proxy, keeping credentials off the client.
  • Replay session live_20261110_214853 completed 10 of 10 windows with 650 events, 270 lane entries, 23 lane changes, and 87 hogging indications across 603 vehicle counts; 13/13 checks passed with 0 quarantined rows.

03 · Lakehouse

NYC Mobility Lakehouse

Databricks Free Edition · NYC TLC Yellow Taxi · Jan–Sep 2024 · Bronze–Silver–Gold

github.com/ibrahim119920/nyc-mobility-lakehouse
Portfolio page · michiportfolio.vercel.app

An idempotent Bronze → Silver → Gold batch pipeline for 30,020,554 NYC TLC Yellow Taxi trips across nine months, built with PySpark, SQL, and Delta Lake.

  • One four-task Job with a replaceWhere overwrite per source_month; the March–September backfill reused the same Job rather than a separate notebook.
  • Idempotency is evidenced by Delta version history and identical checksums before and after a rerun.
  • Gold is reconciled against Silver with zero difference, then used for 12 descriptive analysis queries covering monthly, daily, hourly, zone, payment, and duration patterns.

Photobooth — Local-First Kiosk Prototype

Next.js · SQLite · C++ camera bridge · single device, single active session

Private repository
Portfolio page · michiportfolio.vercel.app

A kiosk prototype where Next.js serves the UI and local backend, SQLite and a local folder are the operational source of truth, and a Local Camera Service is the integration boundary to a USB mirrorless camera.

  • Session state machine with one active session locked in the database, idempotent commands, transactions, audit logs, and local health/backup checks.
  • C++ camera bridge boundary with fake-bridge tests, so the capture flow can be tested without physical hardware.
  • Result media is stored locally before a durable upload queue hands it to cloud storage.
